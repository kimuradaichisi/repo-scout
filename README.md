# RepoScout

RepoScout is a local repository investigation runner that executes evidence-collection
queries generated by commercial coding agents and returns compact, source-grounded evidence.

## Goal

Reduce repository-discovery work performed by commercial coding agents such as Claude Code.

RepoScout does **not** replace the commercial model's reasoning. It offloads broad, repetitive
repository investigation to local deterministic tools.

**Deterministic execution is the default and needs no LLM.** A query names a tool
explicitly (`rg` / `read` / `git_log`) or it comes back `UNRESOLVED` -- RepoScout never
guesses that a query is "probably for Ornith". LLM exploration (a local Ornith worker) is
available but strictly **opt-in**: it only runs when a query sets `tool: ornith` explicitly.
Ambiguous tool selection does not automatically invoke Ornith.

## MVP Scope

Included:

- `rg` text search
- bounded file reads
- `git log`
- single-query Ornith worker
- multi-query investigation plans
- one fresh Ornith invocation per query
- machine-generated Evidence Pack

Not included yet:

- MCP server
- LSP
- AST graph
- implementation delegation
- long-term agent memory
- RAG/vector database

## Architecture

```text
Claude Code
    |
    | Investigation Plan
    v
RepoScout
    |
    +-- tool explicitly set (rg / read / git_log)
    |     +-- deterministic executors
    |           +-- ripgrep
    |           +-- file read
    |           +-- git
    |
    +-- tool == "ornith" (explicit opt-in only)
    |     +-- Ornith worker
    |           +-- OpenCode CLI
    |
    +-- tool unset / unsupported
          +-- UNRESOLVED (no automatic LLM fallback)
    |
    v
Evidence Pack
    |
    v
Claude Code
```

RepoScout treats local model output as **navigation evidence**, not as an authoritative semantic
conclusion. It is never chosen by RepoScout on its own judgment -- only by a caller setting
`tool: ornith` explicitly.

## Requirements

- Python 3.12+
- `uv`
- `rg`
- `git`
- OpenCode available on `PATH` for Ornith queries

## Single deterministic query

```bash
uv run reposcout query \
  --root ../target-repo \
  --id Q1 \
  --tool rg \
  --pattern ExecuteContract \
  --path tools \
  --path tests
```

## Single Ornith query

```bash
uv run reposcout query \
  --root ../target-repo \
  --id Q1 \
  --instruction "ExecuteContract の参照箇所を検索し、ファイル名・行番号・該当行だけ返せ"
```

The default Ornith command is configured in `src/reposcout/ornith/client.py`.
Adjust it to match your OpenCode agent/model setup.

## Investigation Plan

Example:

```yaml
goal: ExecuteContract 変更の影響範囲を調査する

queries:
  - id: Q1
    tool: rg
    pattern: ExecuteContract
    paths:
      - tools
      - tests

  - id: Q2
    tool: read
    file: tools/dev_agent/application/execute_contract.py
    start_line: 1
    end_line: 220

  - id: Q3
    instruction: >
      ExecuteContract を利用するテストを調査し、
      ファイル名・行番号・該当行だけ返せ。
```

Run:

```bash
uv run reposcout investigate \
  --root ../target-repo \
  examples/investigation.yaml
```

Output:

```text
.reposcout/
└── runs/
    └── <run-id>/
        ├── plan.yaml
        ├── Q1.json
        ├── Q2.json
        ├── Q3.json
        └── evidence.md
```

## Repository File Scope

`RepositoryFileScope` is the deterministic file universe Skeleton and Pack both
validate against -- Git's own `.gitignore` matching is the source of truth for
what's in scope, so no directory name (`node_modules`, `.venv`, ...) is
hard-coded anywhere in RepoScout.

Two modes, both scoped to `src` and `tests/unit`:

- `tracked-only` (default) -- `git ls-files`. Unchanged from earlier releases.
- `workspace` -- `git ls-files --cached --others --exclude-standard`: tracked
  files plus untracked-but-not-ignored files (e.g. a file just created, not
  yet `git add`ed).

`include-ignored` (surfacing `.gitignore`d files on purpose) is not
implemented -- see Next Milestones.

```bash
uv run reposcout skeleton --root ../target-repo
uv run reposcout skeleton --root ../target-repo --scope workspace
```

Prints paths in scope -- the deterministic source of truth a caller's
`target_hints` (kind `path`) can be checked against.

## Evidence Pack (Pack First)

Merges and deduplicates requested source ranges into one deterministic Pack,
instead of the caller reading the same or overlapping ranges multiple times.
See [`docs/pack_first_policy.md`](docs/pack_first_policy.md) for when a Strong
Model should call this before individual reads.

```yaml
# request.yaml
ranges:
  - path: src/reposcout/evidence.py
    start_line: 1
    end_line: 20
  - path: src/reposcout/evidence.py
    start_line: 15
    end_line: 30
```

```bash
uv run reposcout pack request.yaml --root ../target-repo
```

Outputs one merged, hashed `PackedSource` per non-overlapping range, plus
`PackMetrics` (`requested_ranges`, `packed_ranges`, `requested_source_bytes`,
`packed_source_bytes`, `duplicate_or_overlap_bytes_eliminated`, `unique_paths`,
`pack_chars`) -- all computed deterministically, with no LLM call involved.

## Core rule

**Planning may be batched. Ornith execution is one query per fresh invocation.**

This intentionally prevents conversation-history contamination between repository investigations.

## Investigation Trace

Investigation Trace records deterministic exploration metadata for later comparison:

```text
Observe -> Compare -> Candidate -> Human Approve -> Policy / Workflow / Tool
```

Trace is observation data, not automatic learning. RepoScout does not infer semantic
coverage, generate rules, or apply policies from a trace. A future analyzer may identify
frequent low-cost paths and propose Rule Candidates, but human approval is required before
promotion.

Tracing is opt-in and writes JSONL, one header or step record per line:

```bash
uv run reposcout investigate examples/investigation.yaml \
  --root ../target-repo \
  --trace-out .reposcout/traces/investigation.jsonl \
  --investigation-id caller-provided-id
```

Each step keeps its sequence, action, executor, query/status, elapsed time, byte/count
metrics, and source path/range/hash metadata. Source bodies are not duplicated in traces;
the Evidence Contract remains their source of truth. The same investigation ID lets a caller
join RepoScout trace data with external model, token, cost, or evaluator telemetry.
